\chapter{Reproduction Commands and Environment}
\label{app:reproduction}

This appendix lists the commands that produced the results and the environment they ran in. All commands are
run from the repository root, \texttt{/home/amal/fyp/\allowbreak Axiom}, with the project virtual environment at \texttt{.venv}.
The Python version was 3.12.13. The packages recorded in the run information of the Duolingo run were
py-fsrs 6.3.2, NumPy 2.5.4, pandas 3.0.6, PyTorch 2.14.1 (CPU build), and Numba 0.68.0. The Anki benchmark
needs access to the gated Hugging Face dataset \texttt{open-spaced-repetition/\allowbreak anki-revlogs-10k}. The Duolingo run needs the
public trace file \texttt{settles.acl16.\allowbreak learning\_traces.13m.csv.gz}, which is not included in the repository.

\section{Hardware}

The Anki benchmark ran on a laptop with 8 cores and 19 GB of RAM, with turbo disabled for the long runs. The Duolingo run
was executed in a separate session on Kaggle, with a T4 GPU for the proposed model.

\section{Anki benchmark (Experiment 2)}

\begingroup\footnotesize\begin{verbatim}
.venv/bin/python -m fsrs_benchmark.run --n_users 100 --max_cards 1000 \
    --seed 0 --iters 2000 --burn 1000 --workers 8 \
    --run_name full_u100_c1000
.venv/bin/python -m fsrs_benchmark.report --run_dir results/full_u100_c1000
.venv/bin/python -m pytest fsrs_benchmark/tests -q
\end{verbatim}
\endgroup

The run writes the predictions, the metrics, the paired bootstrap results and the diagnostics into
\texttt{results/full\_u100\_c1000}. The report step writes \texttt{metrics.csv}, \texttt{paired.csv} and
\texttt{user\_wins.csv} there. The reported pipeline has \NumBenchTests{} automated tests.

\section{Duolingo benchmark (Experiment 3)}

The arguments of the Duolingo run are recorded in \texttt{results/duolingo\_full/\allowbreak run\_info.json}. The command below
reproduces them. The proposed model was run on the GPU through the \texttt{-{}-device auto} option.

\begingroup\footnotesize\begin{verbatim}
.venv/bin/python -m fsrs_benchmark.run --dataset duolingo \
    --duolingo_path data/duolingo/settles.acl16.learning_traces.13m.csv.gz \
    --n_users 0 --max_cards 1000000000 --min_user_rows 1 \
    --models ours_gpu,hlr,laglogit,fsrs_default,fsrs_opt \
    --iters 2000 --burn 1000 --thin 10 --device auto --seed 0 --workers 1 \
    --resume --run_name duolingo_full
.venv/bin/python -m fsrs_benchmark.report --run_dir results/duolingo_full
\end{verbatim}
\endgroup

Setting \texttt{-{}-n\_users 0} uses all 115,222 users. The run directory contains \texttt{run\_info.json}, which records
the counts, the arguments and the package versions. The run was resumable, and \texttt{-{}-resume} reuses finished predictions.

\section{Final runs with the improved models (Experiment 4)}

Experiment~4 used one final run per dataset. Each run fits the earlier models again together with v2, v3 and the GBDT, and its
arguments are recorded in \texttt{run\_info.json} of the run directory. The packages needed beyond those above include
LightGBM 4.6.0. The commands are those of the project's final report.

\begingroup\footnotesize\begin{verbatim}
uv pip install --python .venv/bin/python numpy pandas pyarrow numba scipy \
    matplotlib pytest huggingface_hub "fsrs[optimizer]" torch lightgbm==4.6.0
.venv/bin/python -m fsrs_benchmark.run --n_users 100 --max_cards 1000 \
    --seed 0 --iters 2000 --burn 1000 --resume \
    --run_name full_u100_c1000_final \
    --models fsrs_default,fsrs_opt,hlr,ours,ours_kappa,ours_v2,ours_v3,gbdt
.venv/bin/python -m fsrs_benchmark.run --dataset duolingo --n_users 0 \
    --min_user_rows 1 --max_cards 1000000000 --seed 0 --iters 2000 \
    --burn 1000 --thin 10 --run_name duolingo_final \
    --models ours_gpu,hlr,laglogit,fsrs_default,fsrs_opt,ours_v2,ours_v3,gbdt \
    --device auto --resume
.venv/bin/python -m fsrs_benchmark.report \
    --run_dir results/full_u100_c1000_final
.venv/bin/python -m fsrs_benchmark.report \
    --run_dir results/duolingo_final
\end{verbatim}
\endgroup

The proposed model on Anki takes about 7.6 hours on one CPU core (27,530 seconds), and on full Duolingo it needs a GPU (about 40 minutes on a Kaggle T4). On full
Duolingo the FSRS prediction takes about 40 minutes per variant on four CPUs, v3 fits in about 13 minutes and the GBDT in about 5 minutes. Full Duolingo needs about 6--9 GB of RAM, so only one heavy
job should run at a time on a laptop. The recorded runs used \texttt{-{}-resume}, which reuses finished models, and the device setting \texttt{auto}, which uses the GPU when one is present; the project's final report writes \texttt{-{}-device cuda}. The validation experiments that chose the configurations are in
\texttt{fsrs\_benchmark/experiments}. The tests of the benchmark package should be run one file at a time, because PyTorch and Numba together in one pytest process can hang.

\chapter{Glossary}
\label{app:glossary}

\begin{description}
  \item[AUC] Area under the ROC curve: the probability that a recalled review gets a higher predicted recall than a forgotten one.
  \item[Brier score] The mean squared error between predicted probability and the 0/1 outcome.
  \item[Calibration] Agreement between predicted probabilities and observed frequencies.
  \item[Cold card] A card with no training reviews, for which the prediction restarts the latent state (Section~\ref{sec:method-prediction}).
  \item[ECE] Expected calibration error: the bin-size-weighted mean absolute gap between predicted and observed recall.
  \item[ESS] Effective sample size of an MCMC chain, a measure of how many independent draws it is worth.
  \item[FFBS] Forward filtering and backward sampling, which draws the whole latent path given the observations.
  \item[FSRS-6] The sixth version of the Free Spaced Repetition Scheduler, a deterministic memory model with per-user parameters.
  \item[Gibbs sampling] MCMC that updates each block of parameters in turn from its conditional distribution.
  \item[HLR] Half-life regression, which predicts recall from a half-life that depends on review counts.
  \item[LagLogit+$\Delta t$] A static logistic baseline with the lagged outcome and the gap as inputs.
  \item[Lagged outcome] The recall outcome of the previous review of the same card.
  \item[Latent state] The unobserved scalar $\psi_{n,t}$, the logit of recall, which evolves between reviews.
  \item[Log loss] The mean negative log likelihood of the outcomes under the predicted probabilities.
  \item[MCMC] Markov chain Monte Carlo, a method for drawing from a posterior distribution.
  \item[Metropolis-within-Gibbs] A sampler that uses Metropolis steps for some parameters and Gibbs steps for the others.
  \item[OU process] The Ornstein--Uhlenbeck process, a mean-reverting diffusion, here in the latent state.
  \item[P\'olya--Gamma augmentation] A data-augmentation trick that makes the logistic likelihood conditionally Gaussian.
  \item[Reliability diagram] A plot of observed recall rate against predicted probability, per bin.
  \item[Split $\hat R$] The potential scale reduction factor computed on split chains, a convergence diagnostic.
  \item[Warm card] A card with training reviews, whose prediction starts from its last training state draw.
  \item[$\kappa$] The practice coefficient in $\lambda_{n,t} = \lambda\,e^{-\kappa C_{n,t}}$, where $C_{n,t}$ is the logarithm of one plus the number of successful recalls before review $t$.
  \item[$\lambda$] The base rate at which the latent state is pulled back toward its equilibrium mean.
  \item[$\sigma^2$] The diffusion variance of the latent state.
\end{description}
